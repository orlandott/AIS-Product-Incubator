epistemic·bench

How well do today's leading AI models reason about what they know? We test frontier systems for the habits that matter when machines inform the public, and publish the methodology in full.

Updated August 20, 2026 · Public test set v1

Demonstration data, not real results. Every number on this page was produced by a deterministic stand-in model so the pipeline can be shown end to end offline. It does not reflect how any real AI system performs.

About these numbers

These scores are from the public test set: fully reproducible by anyone, but visible to model developers. The canonical, train-resistant numbers come from a private held-out set, run separately by maintainers; until then, read these as a reproducible reference rather than a leak-proof verdict.

Why there is no single score

These are different qualities, and bundling them into one ranking would invite gaming and hide the trade-offs that matter. Each is reported on its own terms, with its method documented in full, so a strong result on one measure can never paper over a weak one elsewhere.

What we measure

The habits of an honest reasoner

Each quality is scored on its own and its method published in full. Seven are measured here now, and the rest are built to the same standard. There is no blended overall score, by design.

Calibration

Does the model know what it knows? It answers factual questions and must state how sure it is, and then it should be right about as often as it claims, neither bluffing nor needlessly hedging.

Measured now · Calibration

Does the model know what it knows?

We ask 30 multiple-choice factual questions and require each model to state, as a percentage, how sure it is. A well-calibrated model is right about as often as it claims: a model that is 90% sure should be correct roughly nine times in ten. We then compare stated confidence against actual accuracy.

How this was produced

An open benchmark of epistemic behaviour in frontier language models. The public test set is fully reproducible by anyone; a held-out private set guards against training to the test, and the scored operationalisation is rotated between releases. Methods live in methodology/; the full design is in SPEC.md.
